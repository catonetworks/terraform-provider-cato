| Read | policy.ztnaAlwaysOn.policy | PolicyZtnaAlwaysOnPolicy | ZtnaAlwaysOnPolicyInput |
| Update | policy.ztnaAlwaysOn.updatePolicy | PolicyZtnaAlwaysOnUpdatePolicy | ZtnaAlwaysOnPolicyUpdateInput |

The account's Always On policy already exists. Create and Update update its
settings and then call PolicyZtnaAlwaysOnPublishPolicyRevision to publish the
default draft, including all pending changes. Destroy only removes Terraform state.

Update SDK signature:
PolicyZtnaAlwaysOnUpdatePolicy(ctx, accountID,
*ZtnaAlwaysOnPolicyMutationInput, ZtnaAlwaysOnPolicyUpdateInput, interceptors...).

Read SDK signature:
PolicyZtnaAlwaysOnPolicy(ctx, accountID, *ZtnaAlwaysOnPolicyInput, interceptors...).

Use the configured provider account ID and forward request interceptors.
Use nil policy mutation/query inputs for the default draft revision, consistent
with the existing Always On rule and section resources.

The update input is ZtnaAlwaysOnPolicyUpdateInput:

- state: PolicyToggleState (nullable).
  - Enum values: DISABLED, ENABLED.
  - SDK: State *cato_models.PolicyToggleState, JSON state,omitempty.

The SDK input matches the live schema. The user's explicit schema instruction
overrides the skill's generic input-tree and enum mapping: expose only enabled
as a required Terraform boolean. Build API state=ENABLED when enabled=true and
state=DISABLED when enabled=false. Always send a non-nil State pointer, including
when disabling the policy. Do not expose the API state enum as an attribute.

Update returns ZtnaAlwaysOnPolicyMutationPayload with errors, policy, and status.
policy is nullable ZtnaAlwaysOnPolicy. Read returns non-null ZtnaAlwaysOnPolicy.
The policy contains audit, enabled, revision, rules, and sections. enabled is a
non-null Boolean, present in both SDK operation selections. Read this boolean
directly into Terraform enabled; it is required, not computed.

Audit and revision are publication/operation metadata outside this resource's
toggle configuration. Rules and sections are managed by cato_always_on_rule and
cato_always_on_section. Do not expose policy snapshots of those collections in
this resource. No SDK discrepancy affects the proposed toggle attributes.

## Schema and lifecycle

See schema_description.yaml. The sole attribute is enabled: required bool.
There are no id or state attributes, including computed identifiers.

The resource follows existing singleton policy resource behavior while using
only the two APIs authorized by the user:

- Terraform Create applies the requested enabled value through updatePolicy and then
  reads the existing policy. It does not create a remote policy.
- Terraform Read refreshes enabled from the singleton using policy.
- Terraform Update applies enabled through updatePolicy and reads it back. Check
  transport errors, mutation errors/status, and the returned read structure.
  Require the observed enabled value to match the requested boolean; do not hide
  an unsuccessful update by copying the plan into state.
- Terraform Delete removes Terraform state without any API call, leaving the
  policy and its last configured state intact.
- Import accepts the configured account ID, as explicitly chosen by the user.
  It rejects a mismatched account and hydrates enabled without any mutation or
  added identifier attribute. Example:
  terraform import cato_always_on_policy.example 123456.

Manage the account singleton with one Terraform resource instance. Do not add
account_id, revision selection, publication controls, or rule/section ownership
to the resource schema.

## Implementation and verification

The Terraform model, schema, lifecycle, converters, and narrow ResourceClient
adapter are in separate resource-specific files. Existing uncommitted
cato_always_on_section work is preserved. AlwaysOnPolicyClient is generated by
pinned make mocks; do not edit it manually. No SDK dependency update is needed.

Create and Update share the mutation lifecycle and stop on transport errors,
payload errors, or a missing/non-success status. After a successful mutation,
they read the policy and verify enabled matches the plan before saving state.
Read failures and mismatches produce diagnostics without overwriting prior state.
The SDK decodes the non-null policy object and enabled boolean as Go values;
the parser also checks the required rules/sections lists to reject a missing
policy that would otherwise appear to be disabled. These lists are not exposed
as Terraform attributes.

Unit tests cover schema, lifecycle, import account matching, boolean-to-enum
conversion, null/unknown inputs, disabled=false handling, malformed reads,
mutation errors/status, inconsistent read-after-update results, and account,
revision, and interceptor forwarding. Delete and import tests ensure no mutation
API calls. Initial focused test coverage is 97.9%.

Acceptance coverage in internal/acctests/always_on_policy changes and publishes the toggle,
restores its original value, verifies import, and lets Terraform forget the resource.
Fallback cleanup restores the original value on failure. It uses account 62015,
uses DISABLE_POLICY_RULE_CLEANUP=true, and publishes all pending draft changes. Do not run acceptance tests without authorization specific to this
policy work; the previous authorization covered section testing.

The complete example and import command are under examples/resources/cato_always_on_policy.
